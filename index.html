Saving deposits lost to technical glitches

Problem
A brief backend failure failed the customer's fixed deposit and turned it into a support ticket with a 1–2 day wait.
What I did
Dug into the failure funnel with ops and backend teams and found ~70% of failures fixed themselves within minutes. Redesigned the journey to retry quietly in the background and took it from spec to launch.
Key decision
Retry first, and raise a ticket only after every retry fails, so most customers never see the failure.
~80%expected drop in a targeted fraud pattern

Protecting elderly customers from deposit fraud

Problem
Fraudsters talked elderly customers into closing their fixed deposits and moving the money out right away. Each step looked normal on its own, so standard checks missed it.
What I did
Traced the pattern through support and ops data and defined the risk signals with our fraud analytics partner. Then designed Trusted Guardian: an elderly customer names someone they trust, who can verify flagged payments before the money moves.
Key decision
Bring in the guardian only for flagged cases, not every payment, so everyday banking stays smooth.

Business rule changes without a release

Problem
Deposit closure and overdraft creation ran on two near-identical APIs. Changing even an interest-rate rule took code, a sprint slot and a release: 1–2 weeks.
What I did
Designed one API for both journeys with rules moved from code into config, and shipped an admin portal where the business team edits them directly.
Key decision
Merge the two APIs instead of patching each one: more work upfront, but no engineering dependency for future regulatory changes.

upsorb: see where every student is stuck, and fix it

An AI homework platform for schools that want to raise teaching quality. Students get hints, not answers. Teachers see exactly where each student is stuck, and fix it in a click with personalised actions.

01 · The problem

Teachers can't see who is lacking where

Today's LMS tools show scores, not why a student scored low: which topic, at which level of understanding. And they stop there, with no way to act on it. Students, meanwhile, copy answers from AI and learn nothing.

I spoke with 20 educators. What they told me:

  • Checking homework eats hours every week.
  • Competency-based learning under NEP is hard to deliver with today's tools.
  • Tools don't talk to each other, so teachers move data back and forth by hand.
  • AI isn't accurate enough to trust without checking.

02 · The solution

One loop: set → learn → diagnose → act

Teachers set homework in minutes. Students solve it with an AI tutor that guides instead of answering. Every answer is graded by subtopic and depth of understanding (Bloom's levels), and the Action Lab turns that into groups and a ready lesson plan, all in one place.

03 · Making AI calls cheap

Measured every call, then cut cost and wait time

AI cost / student / month₹325 → ₹94

  1. Per-call cost loggingTokens, cost and latency on all 12 AI features. Caught a retry bug billing each grade 2–3×.
  2. Model routingCheap vision model for photos; fast open model for tutoring and grading.
  3. Prompt cachingFixed prompt prefixes, so 96% of tutor input tokens hit the cache.
  4. Reasoning cap"Medium" thinking: 4× faster than default, same quality. "Low" missed mistakes.
  5. Parallel + async callsIndependent analysis steps run in parallel; heavy jobs run in the background.
  6. Batch gradingDesigned to grade a homework's answers in one batch (~27% cheaper); rolling out.

Measured on test homeworks before launch: directional, not production averages.

04 · Prompting for quality

Better context in, better answers out

  • Grounded in the syllabus: lesson plans get exact NCERT subtopics, prerequisites and page numbers, with a rule to never invent.
  • Chained prompts: diagnosis runs in 3 steps (what the question tests → knowledge type → thinking level), each with its own reference guide.
  • Full context per student: the tutor sees the question, the hidden solution and the student's last 3 attempts.
  • Checked outputs: every structured reply is validated and retried if broken.
  • Tutor that holds back: 8 prompt versions to a 5-level hint ladder that adapts to each reply.

05 · Key decisions

Hints, not answers
Students already use AI to skip thinking. Guiding keeps the learning theirs.
Quality over cost
Kept reasoning on for tutoring and grading, even though publishing is slower.
Scope the tutor
Homework questions only, no open chat: predictable cost, focused students.
